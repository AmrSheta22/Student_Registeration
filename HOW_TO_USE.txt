ALEXANDRIA UNIVERSITY — STUDENT REGISTRATION GUIDE
================================================

1. BEFORE YOU START
-------------------
You need Python 3.10+, Google Chrome, a compatible ChromeDriver, internet
access, and a portal account with registration/report access.

Open PowerShell in the Student_Registration folder and install dependencies:

    python -m pip install -r requirements.txt

Keep each input file limited to ONE department/program. IDs must be nonempty
and unique. Back up your input file and close it in Excel before running.

IMPORTANT: Never close the website during an active session. Log out and
confirm logout is complete first. The scripts leave Chrome open, including
on errors. If automatic logout fails, leave the tab open and log out manually.
Do not interfere with the controlled tab while the script is working.

The current academic scope is 2026/2027, Fall.


2. REGISTER MULTIPLE SUBJECTS PER STUDENT (XLSX)
----------------------------------------------
Prepare registeration.xlsx:

- First column: ID (student_id also works).
- Other column headers: full portal course labels, including course code,
  year, semester, group and level. Each group has its own column.
- Put 1 in a student/subject cell to request registration.
- Leave unrequested cells blank or enter 0.
- Keep headers unique and avoid formulas in request cells.

Small spacing and spelling differences are tolerated. The matcher protects
course code, group, year and semester and does not submit ambiguous matches.

START A NEW RUN — first two students in the intelligent-systems program:

    python alexu_batch_add_course_registration.py registeration.xlsx --program "برنامج النظم الذكية" --limit 2

Enter your username and password when prompted. The password is hidden.
Omit --limit 2 to process all students. These commands submit real registrations
for every marked subject in the selected rows.

The script registers each student's requested subjects on the same page,
then moves to the next student. It adds a Registration log sheet to the SAME
workbook and saves after each subject. The input sheet is preserved.

RESULTS IN REGISTRATION LOG

    succeeded
        The portal confirmed registration.

    Failed: already registered or group closed
        The requested subject could not be found or selected.

    Failed: student not found in selected program
        The portal did not find the student in the chosen program.

    Failed: <notification text>
        The portal rejected the subject. Brief error notifications are
        captured before they disappear, and processing continues.

    Failed: skipped without retry; outcome unconfirmed (...)
        An unexpected error prevented confirmation. The subject is skipped;
        its actual registration status must be checked on the portal.

    pending
        Requested but not yet processed. Unrequested cells stay blank.

AUTOMATIC RECOVERY

After an unexpected subject error, the script saves the result, confirms
logout, logs in again with the same credentials and academic scope in the
same open Chrome session, and continues with the next subject. It does not
retry the affected subject. Confirmed results are retained.

If logout cannot be confirmed, reconnection fails, or a checkpoint cannot be
saved, the run stops and Chrome stays open. Failure diagnostics are saved to
alexu_batch_registration_failure.png when possible.


3. CONTINUE AN INTERRUPTED XLSX RUN
----------------------------------
Keep the existing Registration log sheet. Save and close Excel, then use:

    python alexu_batch_add_course_registration.py registeration.xlsx --program "برنامج النظم الذكية" --resume

This processes blank/pending requested cells and skips successes and failures,
including subjects marked "skipped without retry". Do not delete the log or
start from a fresh copy to resume: doing so loses the record of prior attempts.

TO START AT A PARTICULAR STUDENT, INCLUDING THEIR REMAINING SUBJECTS:

    python alexu_batch_add_course_registration.py registeration.xlsx --program "برنامج النظم الذكية" --resume --start-student 2403258321

Replace 2403258321 with the student ID you want. The starting student is
included. Later students are processed in input-sheet order.

Add --limit 2 to process only two students from that starting position.
Completed students still count toward this limit.

TO RETRY CONFIRMED FAILURES AS WELL AS PENDING REQUESTS:

    python alexu_batch_add_course_registration.py registeration.xlsx --program "برنامج النظم الذكية" --resume --retry-failed

Successes are always skipped. Before retrying an unconfirmed result, check
that student/subject on the portal and update its log cell:

- succeeded: registration is confirmed.
- Failed: <reason>: rejection is confirmed.
- pending: not registered, and you want another attempt.

Older cells containing "outcome unconfirmed" without "skipped without retry"
must be resolved before normal resume. New skipped/unconfirmed cells can be
skipped during normal resume, but must be resolved before --retry-failed.

Do not reorder input rows or change course headers independently of the log.
Resume checks that log headers and student IDs still match the input.


4. REGISTRATION OPTIONS
-----------------------
    --program "<exact program name>"   Choose the department/program.
    --year "2026/2027"                 Academic year; current default shown.
    --semester Fall                    Semester; current default shown.
    --sheet "Sheet1"                   Choose the input worksheet.
    --limit 2                          Limit the number of students.
    --resume                           Continue using the existing XLSX log.
    --start-student <ID>                Start at this ID, inclusively.
    --retry-failed                     With --resume, retry confirmed failures.
    --username <username>              Supply the username; password stays hidden.

Without --sheet, the first worksheet is used as input.
Resume, start-student and limit behavior above applies to XLSX registration.

Available programs (also shown in the interactive menu):

    1. برنامج الحوسبة وعلوم البيانات
    2. برنامج تحليلات الأعمال
    3. برنامج النظم الذكية
    4. برنامج تحليلات الوسائط الإعلامية
    5. برنامج تحليلات ومعلوماتية الرعاية الصحية
    6. برنامج الأمن السيبراني

If --program is omitted, ALEXU_PROGRAM is used when set; otherwise registration
shows the menu. Pressing Enter chooses program 1, so choose your department.
The requested year and semester must exist in the portal and match the course
headers. The script does not silently switch to another academic scope.


5. REGISTER ONE SUBJECT FOR A CSV BATCH
--------------------------------------
Use this older workflow when every student needs the same subject.
The CSV must have a student_id column; other columns are preserved.

    python alexu_batch_add_course_registration.py data.csv

Choose the program, then choose one course from the first valid student's
available courses. The script attempts that course for all students and saves
course_registration_status after each student: pending, succeeded or failed.

Every CSV run resets previous statuses to pending. CSV has no log-based resume
or per-subject automatic logout/relogin recovery. Do not use the XLSX resume
options for CSV batches; prepare a CSV containing only students you intend
to process and verify previous registrations before repeating a run.


6. GET COMPLETED CREDIT HOURS (CSV)
----------------------------------
Prepare a CSV with a student_id column, for example:

    student_id,name
    2401241123,Student One
    2401241158,Student Two

Run:

    python student_completed_hours_pipeline.py data.csv

Choose the program and enter credentials when prompted. The script retrieves
lecture-table PDFs, extracts Completed: X Hrs, and updates completed_hours.
Missing students receive unknown. PDFs are saved to output/pdf/<student_id>.pdf.

The CSV is replaced only after the entire batch succeeds. On an unexpected
failure, the script stops, attempts logout and leaves Chrome open. Saved PDFs
remain, but rerunning starts from the beginning; this workflow has no resume
or automatic logout/relogin recovery.

Year and semester are set by ACADEMIC_YEAR and SEMESTER in
student_completed_hours_pipeline.py, currently 2026/2027 and Fall. This script
does not accept --year or --semester. Registration imports these defaults,
but allows its own command-line overrides.

Completed-hours options:

    --program "<exact program name>"
    --username <username>
    --pdf-dir "output/pdf"
    --timeout 60
    --failure-screenshot "alexu_failure.png"

PDF extraction depends on Chrome's disk cache and readable PDF text. A portal
or Chrome change may require code updates.


7. CREDENTIALS AND COMMON PROBLEMS
---------------------------------
Prefer the interactive hidden password prompt. Both scripts also read
ALEXU_USERNAME, ALEXU_PASSWORD and ALEXU_PROGRAM from environment variables.
Do not put passwords in source files or command-line arguments.
XLSX registration can run without prompts when credentials and program are
supplied. Single-course CSV registration still prompts for a course.

File locked / permission denied:
    Close Excel and ensure the input folder is writable. File replacement
    retries Windows permission errors for up to 30 seconds.

Registration log already exists:
    Continue with --resume. Preserve completed results.

Requested year, semester or program unavailable:
    Check the portal's available options and the input's academic scope.

Outcome unconfirmed:
    Verify the portal before retrying. Update the log as described in section 3.

Logout not confirmed:
    Leave the website open. Complete logout manually and verify the login page
    before closing the tab. Automatic confirmation checks the visible username
    and password fields and absence of the authenticated avatar.

Keep workbooks, CSVs, PDFs and screenshots private: they contain student data.

To see each script's available options:

    python alexu_batch_add_course_registration.py --help
    python student_completed_hours_pipeline.py --help
